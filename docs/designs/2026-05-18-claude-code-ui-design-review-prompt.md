# Claude Code UI Design Review Prompt

このファイルを Claude Code に読ませて、Web アプリ UI のデザイン改修案を出させるための指示書です。

## 依頼

このリポジトリの Web アプリ UI をレビューして、デザイン改修案を出してください。

## 重要な前提

- まだコードは変更しないでください。
- まず既存の画面構成、コンポーネント、CSS、主要ワークフローを読んでください。
- 必要ならローカルアプリ `http://127.0.0.1:8000` を確認してください。
- 出力は日本語で、実装タスクに落とし込める粒度にしてください。
- 実装を始める前に、改善方針と優先順位を明確にしてください。

## 対象アプリ

Agent Refinement Platform は、AI エージェント同士を会話・協調させながら、文章推敲、設計レビュー、コーディング相談、ワークスペース管理を行うローカル実行プラットフォームです。

主な画面:

- Dashboard
- Workspace
- Coding
- Agent Studio
- Team Composer
- Skills
- Knowledge
- Logs
- Settings

## 今回の目的

見た目を派手にすることではなく、毎日使う作業アプリとして、情報設計、操作性、視認性、状態の分かりやすさ、画面密度、導線を改善したいです。

SaaS / 開発支援ツールらしい、落ち着いていて実務的な UI にしてください。

## 見てほしい観点

1. ナビゲーションと画面構造が分かりやすいか。
2. Workspace / Coding の主要ワークフローが迷わず使えるか。
3. 情報量が多い画面で、視線誘導、余白、区切り、優先順位が適切か。
4. ボタン、フォーム、状態表示、ログ、進捗表示の UI が一貫しているか。
5. エージェント、チーム、スキル、ワークスペースの関係が UI 上で理解しやすいか。
6. 空状態、読み込み中、エラー、実行中、完了状態が十分に設計されているか。
7. モバイル対応よりも、まずデスクトップ作業環境での使いやすさを優先できているか。
8. アクセシビリティ、コントラスト、文字サイズ、クリック領域に問題がないか。

## 制約

- ランディングページ風にはしないでください。
- 派手な装飾や大きすぎるヒーロー表現は避けてください。
- 既存機能は削らないでください。
- 装飾的なカードの多用は避け、作業効率を上げる方向で提案してください。
- 実務向け SaaS / 開発支援ツールらしい落ち着いた UI にしてください。
- 開発コストが高すぎる全面刷新ではなく、段階的に実装できる提案にしてください。
- ただし、必要なら情報設計やレイアウトの大きな見直しも提案して構いません。

## 出力形式

以下の構成で日本語でまとめてください。

### 1. 総評

現在の UI の良い点、課題、最も優先すべき改善テーマを短くまとめてください。

### 2. 優先度順の改善案

P0 / P1 / P2 に分けて、改善内容、理由、期待効果を書いてください。

### 3. 画面別の改修案

次の画面ごとに、具体的な UI 変更案を書いてください。

- Dashboard
- Workspace
- Coding
- Agent Studio
- Team Composer
- Skills
- Knowledge
- Logs
- Settings

特に Workspace と Coding は、左右ペイン、中央作業領域、右側ログ / レビュー領域の最適な分割を具体的に示してください。

### 4. コンポーネント設計

共通化すべき UI コンポーネント、状態表示、ボタン、フォーム、タブ、サイドバー、ログビュー、進捗表示の改善案を書いてください。

### 5. ビジュアル方針

色、タイポグラフィ、余白、境界線、アイコン、カード、テーブル、パネルの設計方針を具体的に書いてください。

### 6. 実装しやすい改修ステップ

短期、中期、長期の順で、実装タスクに落とし込める粒度で書いてください。

### 7. 次に Claude Code へ渡す実装プロンプト

最後に、上記提案をもとに Claude Code へ渡せる実装プロンプトを作成してください。

## 補足

可能であれば、主要画面の改修後レイアウトをワイヤーフレームまたは画面構成案として提示してください。

このレビューではコード変更を行わず、まず改修案の整理に集中してください。
